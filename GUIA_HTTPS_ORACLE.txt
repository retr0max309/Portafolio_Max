PORTAFOLIO MAX: DESPLIEGUE HTTPS EN ORACLE CLOUD
===============================================

1. OBJETIVO Y DIRECCIÓN

El portafolio se publica en:
  https://portafolio.168-138-148-187.sslip.io/

El servicio DNS gratuito sslip.io resuelve el nombre incorporando la IP
pública 168.138.148.187 de la VM. El nombre permite obtener un certificado
TLS válido sin comprar un dominio. Si cambia la IP de la VM, hay que cambiar
el nombre y solicitar un certificado nuevo.

Recorrido de una visita:
  Navegador -> HTTPS:443 de la VM -> Nginx -> 127.0.0.1:8080 ->
  contenedor Next.js -> API NestJS -> Supabase PostgreSQL.

2. INFRAESTRUCTURA CON TERRAFORM

Terraform creó una VM Ubuntu 24.04, VCN, subred pública, Internet Gateway,
tabla de rutas, lista de seguridad e IP pública en Oracle Cloud. La lista de
seguridad permite HTTP 80 y HTTPS 443; SSH 22 está limitado a la IP del
administrador. Terraform guarda el estado en un bucket privado de OCI.

3. CONFIGURACIÓN INICIAL CON SCRIPTS BASH

scripts/deploy-vm.sh instala Git, Docker Engine y Docker Compose en Ubuntu.
Configura iptables para aceptar 80 y 443, aceptar SSH desde la IP autorizada
y bloquear otros accesos SSH. Guarda las reglas para los reinicios. Copia el
Compose y las variables de producción a /opt/portafolio, descarga las imágenes
de Docker Hub y arranca la web y la API.

compose.prod.yml publica la web únicamente en 127.0.0.1:8080 de la VM. El
puerto 8080 no se expone a Internet; solo Nginx se comunica con él.

scripts/configure-https-vm.sh instala Nginx y Certbot. Nginx escucha 80 y 443,
reenvía las solicitudes a Next.js y redirige HTTP a HTTPS para el nombre
sslip.io. Certbot valida el nombre por el puerto 80 y obtiene un certificado
de Let's Encrypt. certbot.timer lo renueva y recarga Nginx al renovarlo.

4. DESPLIEGUE AUTOMÁTICO EN GITHUB ACTIONS

Cada push a dev ejecuta .github/workflows/all-tests.yml: revisión de tipos,
pruebas unitarias, de integración, E2E y compilación.

Cada push a main ejecuta .github/workflows/terraform-vm.yml: repite las
pruebas, comprueba y aplica Terraform sin permitir eliminaciones o reemplazos
automáticos, construye las imágenes Docker de Next.js y NestJS, las publica en
Docker Hub con etiquetas sha-<commit> y latest, y usa OCI Run Command para
instalar la nueva versión en la VM.

Dentro de la VM, scripts/remote-release.sh descarga el compose.prod.yml del
commit publicado, fija IMAGE_TAG=sha-<commit>, descarga las dos imágenes,
actualiza los contenedores y comprueba HTTP local y HTTPS público. Las
credenciales de Supabase permanecen en /opt/portafolio/.env.production;
no se suben a Git ni se incluyen en el comando remoto.

5. COMPROBACIONES MANUALES DESDE POWERSHELL

  Resolve-DnsName portafolio.168-138-148-187.sslip.io -Type A
  curl.exe -I http://portafolio.168-138-148-187.sslip.io/
  curl.exe -I https://portafolio.168-138-148-187.sslip.io/

El primer comando debe resolver 168.138.148.187. HTTP debe responder 301
hacia HTTPS y HTTPS debe responder 200. curl.exe verifica el certificado;
no uses -k porque desactivaría esa comprobación.

Abre la URL HTTPS en un navegador, revisa los proyectos y envía un mensaje de
contacto. Después comprueba el registro en contact_messages de Supabase.

Para comprobar servicios dentro de la VM:
  $sshKey = 'C:\Users\NITRO\Documents\Proyecto-Sistemas III\TareasFinales\ssh-key-2026-10-01.key'
  $vm = 'ubuntu@168.138.148.187'
  ssh -i $sshKey $vm 'systemctl is-active nginx certbot.timer'
  ssh -i $sshKey $vm 'sudo ss -ltnp | grep -E ":(80|443|8080) "'
  ssh -i $sshKey $vm 'sudo certbot certificates'
  ssh -i $sshKey $vm 'sudo docker compose --env-file /opt/portafolio/.env.production -f /opt/portafolio/compose.prod.yml ps'

Nginx debe escuchar 80 y 443; Docker debe publicar 8080 solo en 127.0.0.1.
nginx y certbot.timer deben estar activos y ambos contenedores saludables.
